    011 - 自指与可计算性

    在本节课中，我们将探讨证明与计算之间的深刻联系。这种联系的核心是自指（Self-reference）的概念，它对计算的极限（停机问题）以及数学逻辑的基础（哥德尔不完备定理）产生了深远的影响。

    1 说谎者悖论

    回想一下，命题是或真或假的陈述。我们在之前的课程中看到，有些陈述定义不明确或过于模糊，不能被称为命题。但这里有一个陈述，由于更微妙的原因而存在问题：

    “所有克里特岛人都是说谎者。”

    这是古代一位克里特岛人说的，从而引发了所谓的说谎者悖论，几个世纪以来一直让人们感到有趣和困惑。为什么呢？因为如果上面的陈述是真的，那么那个克里特岛人就在撒谎，这暗示该陈述是假的。但实际上，上述陈述并不是一个真正的悖论；如果我们假设它是真的，它只是产生了一个矛盾，但如果它是假的，就没有问题。

    这个悖论的一个真正表述是以下陈述：

    “本陈述是假的。”

    上面的陈述是真的吗？如果该陈述是真的，那么它所断言的内容必须是真的；即它是假的。但如果它是假的，那么它必须是真的。所以它确实是一个悖论，我们看到它产生于该陈述的自指性质。大约一个世纪前，这个悖论成为了数学和计算基础问题的核心。

    我们现在将研究这个悖论如何与计算建立联系。在此之前，让我们考虑一下由伟大的逻辑学家伯特兰·罗素（Bertrand Russell）创造的悖论的另一种表现形式。在一个只有一个理发师的村庄里，每个男人都保持着刮干净胡子的习惯。有些男人自己刮胡子，而有些男人则去理发师那里。理发师宣布：

    “我给所有且仅给那些不给自己刮胡子的人刮胡子。”

    那么，问一个问题似乎是合理的：理发师给自己刮胡子吗？然而，仔细思考这个问题，我们看到，假设理发师的话是真的，我们就会面临同样的自指悖论：一个逻辑上不可能的情景。如果理发师不给自己刮胡子，那么根据他的声明，他会给自己刮胡子。如果理发师给自己刮胡子，那么根据他的声明，他就不会给自己刮胡子！

    2 自复制程序

    我们可以利用自指来设计一个输出自身的程序吗？为了说明这个想法，让我们考虑一下如果我们可以用英语编写程序，该如何实现。考虑以下指令：

    打印出以下句子：

    “打印出以下句子：”

    如果我们执行上面的指令（将其解释为程序），那么我们将得到以下输出：

    打印出以下句子：

    显然，这与上面的原始指令不同，原始指令由两行组成。我们可以尝试按如下方式修改指令：

    将以下句子打印两次：

    “将以下句子打印两次：”

    执行此修改后的指令产生的输出现在由两行组成：

    将以下句子打印两次：

    将以下句子打印两次：

    这几乎可行，除了第二行缺少引号。我们可以通过如下修改指令来修复它：

    将以下句子打印两次，第二次带引号：

    “将以下句子打印两次，第二次带引号：”

    然后我们看到，当我们执行这条指令时，我们得到的输出与指令本身完全相同：

    将以下句子打印两次，第二次带引号：

    “将以下句子打印两次，第二次带引号：”

    2.1 奎恩程序与递归定理

    在上面的章节中，我们看到了如何用英语编写一个自复制程序。但是我们能用真实的编程语言做到这一点吗？通常，一个打印自身的程序被称为奎恩程序（Quine），1 事实证明，我们总是可以用任何编程语言编写奎恩程序。

    作为另一个例子，考虑以下伪代码：

    (Quine “s”)

    (s “s”)

    上面的伪代码定义了一个程序 Quine，它将字符串 s 作为输入，并输出 \(( \mathsf { s } ^ { \mathrm { ~ \tiny ~ \mathfrak ~ { ~ \mathfrak { ~ c ~ } ~ } ~ } } )\) ，这意味着我们在字符串 s 本身上运行该字符串（此时将其解释为程序）。现在考虑以 “Quine” 作为输入执行程序 Quine：

    (Quine “Quine”)

    根据定义，这将输出

    (Quine “Quine”)

    这与我们执行的指令完全相同！

    这是一个简单的例子，但我们如何构造通用的奎恩程序呢？答案由递归定理（Recursion Theorem）给出。递归定理指出，给定任何程序 \(P ( x , y )\) ，我们总是可以将其转换为另一个程序 \(Q ( x )\) ，使得 \(Q ( x ) = P ( x , Q )\) ，即 \(Q\) 的行为与 \(P\) 在其第二个输入是程序 \(Q\) 的描述时的行为完全相同。从这个意义上说，我们可以将 \(Q\) 看作是 \(P\) 的“自我意识”版本，因为 \(Q\) 实际上可以访问它自己的描述。

    3 停机问题

    是否存在计算机无法完成的任务？例如，我们想在编译程序时询问以下基本问题：它会进入死循环吗？1936 年，艾伦·图灵（Alan Turing）证明了不存在可以执行此项测试的程序。这个引人注目的事实的证明非常优雅，并结合了两个要素：自指（如说谎者悖论）以及我们无法将程序与数据分离的事实。在计算机中，程序由一串位（bits）表示，就像整数、字符和其他数据一样。唯一的区别在于如何解释这串位。

    我们现在将研究停机问题。给定一个程序的描述及其输入，我们想知道该程序在给定输入上执行时是否会停机。换句话说，我们想编写一个程序 TestHalt，其行为如下：

    \[ \operatorname {T e s t H a l t} (P, x) = \left\{ \begin{array}{l l} \text {" y e s "}, & \text {如果程序 P 在输入 x 上停机} \\ \text {" n o "}, & \text {如果程序 P 在输入 x 上死循环} \end{array} \right. \]

    为什么这样的程序不存在？首先，让我们利用程序只是位串这一事实，因此它可以作为数据输入。这意味着考虑 TestHalt(P,P) 的行为是完全有效的，如果 \(P\) 在 \(P\) 上停机，它将输出 “yes”；如果 \(P\) 在 \(P\) 上永远死循环，它将输出 “no”。我们现在证明这样的程序不存在。

    定理 11.1。停机问题是不可计算的；也就是说，不存在在所有输入 \(( P , x )\) 上都具有上述指定行为的计算机程序 TestHalt。

    证明。假设为了矛盾（反证法），存在程序 TestHalt。那么我们可以用它来构造以下程序：

    Turing(P) 
    如果 TestHalt(P, P) = "yes" 那么 
        永远死循环 
    否则 
        停机

    因此，如果程序 \(P\) 在给定 \(P\) 作为输入时停机，那么 Turing(P) 永远死循环；否则，Turing(P) 停机。假设我们有程序 TestHalt，我们可以很容易地在上述程序 Turing 中将其用作子程序。

    现在让我们看看 Turing(Turing) 的行为。有两种情况：要么它停机，要么它不停机。如果 Turing(Turing) 停机，那么 TestHalt(Turing,Turing) 必定返回了 “yes”。但根据 TestHalt 的定义，这意味着 Turing(Turing) 不应该停机。在第二种情况下，如果 Turing(Turing) 不停机，那么 TestHalt(Turing, Turing) 必定返回了 “yes”，这意味着 Turing(Turing) 应该已经停机了。

    在两种情况下，我们都得出了矛盾，这必定意味着我们最初的假设，即程序 TestHalt 存在，是错误的。因此，TestHalt 不可能存在，所以程序无法检查任何通用程序是否停机！ \(\square\)

    我们使用了什么证明技巧？这实际上是一个对角线法（Diagonalization）证明，与我们在上一讲中用来证明实数不可数的技术相同。为什么呢？因为所有计算机程序的集合是可数的（毕竟它们只是某些字母表上的有限长度字符串，而所有有限长度字符串的集合是可数的），我们可以将所有程序列举如下（其中 \(P _ { i }\) 代表第 \(i\) 个程序）：

    \[ \begin{array}{c} P _ {0} \quad P _ {1} \quad P _ {2} \quad P _ {3} \quad P _ {4} \dots \\ P _ {0} \boxed {\widehat {\mathbb {H}} \texttt {L H L H} \dots} \\ P _ {1} \boxed {\texttt {L} \texttt {L} \texttt {H} \texttt {L} \dots} \\ P _ {2} \boxed {\texttt {H} \texttt {H} \widehat {\mathbb {H}} \texttt {H} \texttt {L} \dots} \\ P _ {3} \boxed {\texttt {H} \texttt {H} \texttt {H} \widehat {\mathbb {H}} \texttt {H} \dots} \\ \vdots \end{array} \]

    上表中的 \(( i , j )\) 项，如果程序 \(P _ { i }\) 在输入 \(P _ { j }\) 上停机，则为 H；否则为 L（代表 “Loops”，即死循环）。现在，如果程序 Turing 存在，它必然出现在我们的程序列表中，假设为 \(P _ { n }\)。但这不可能，因为如果对角线上的第 \(n\) 项是 H，意味着 \(P _ { n }\) 在 \(P _ { n }\) 上停机，那么根据其定义，Turing 在 \(P _ { n }\) 上死循环；如果该项是 L，那么根据定义，Turing 在 \(P _ { n }\) 上停机。因此，Turing 的行为与 \(P _ { n }\) 不同，因此 Turing 不会出现在我们的列表中。由于该列表包含所有可能的程序，我们必须得出结论，程序 Turing 不存在。又因为 Turing 是通过对 TestHalt 的简单修改构造出来的，我们可以得出结论 TestHalt 也不存在。因此，停机问题无法解决。

    事实上，还有许多关于程序的问题我们想要回答但却无法回答。例如，我们无法知道一个程序是否会有任何输出，或者它是否会执行特定的某一行。我们也无法检查两个程序是否产生相同的输出。我们还无法检查一个给定的程序是否是病毒。这些问题在高级课程 CS172（可计算性与复杂性）中有更详细的探讨。

    3.1 简单停机问题

    如上所述，确立停机问题不可计算性的关键思想是自指：给定一个程序 \(P\) ，当我们要判定 \(P ( P )\) 是否停机时，我们遇到了麻烦。但在实践中，我们有多少次想要以程序自身的描述作为输入来执行它呢？是否可能如果我们禁止这种自指，我们就可以解决停机问题？

    例如，给定一个程序 \(P\) ，如果我们改问这样一个问题：“\(P\) 在输入 0 时会停机吗？”这看起来比停机问题更容易（因此得名“简单停机问题”），因为我们只需要检查 \(P\) 是否在特定的输入 0 上停机，而不是在任意给定的输入（例如 \(P\) 本身）上停机。然而，事实证明这个看似更容易的问题仍然是不可计算的！我们通过证明以下结论来证实这一主张：如果我们能解决简单停机问题，那么我们也能解决停机问题本身；既然我们知道停机问题是不可计算的，这意味着简单停机问题也必定是不可计算的。

    具体来说，假设我们有一个程序 TestEasyHalt 可以解决简单停机问题：

    \[ \text {T e s t E a s y H a l t} (P) = \left\{ \begin{array}{l l} \text {" y e s "} , & \text {如果程序 P 在输入 0 上停机} \\ \text {" n o "} , & \text {如果程序 P 在输入 0 上死循环} \end{array} \right. \]

    然后我们可以将 TestEasyHalt 作为一个子程序，用于以下解决停机问题的算法：

    Halt(P, x)
    构造一个程序 P'，它在输入 0 时返回 P(x)
    返回 TestEasyHalt(P')

    算法 Halt 构造了另一个程序 \(P ^ { \prime }\) ，它取决于原始程序 \(P\) 和原始输入 \(x\) ，使得当我们调用 \(P ^ { \prime } ( 0 )\) 时，我们返回 \(P ( x )\) 。这样一个程序 \(P ^ { \prime }\) 可以非常简单地构造如下：

    P'(y) 返回 P(x)

    也就是说，新程序 \(P ^ { \prime }\) 忽略其输入 \(y\) ，始终返回 \(P ( x )\) 。（注意，\(P\) 和 \(x\) 的描述是被“硬编码”到 \(P ^ { \prime }\) 中的。）然后我们看到 \(P ^ { \prime } ( 0 )\) 停机当且仅当 \(P ( x )\) 停机。因此，如果我们有这样一个程序 TestEasyHalt，那么 Halt 将正确解决停机问题。既然我们知道不可能存在这样的程序 Halt，我们得出结论 TestEasyHalt 也不存在。

    我们在这里使用的技术被称为规约（Reduction）。在这里，我们将一个问题“\(P\) 在 \(x\) 上停机吗？”规约为另一个问题“\(P ^ { \prime }\) 在 \(0\) 上停机吗？”，其意义在于：如果我们知道如何解决第二个问题，那么我们就可以利用该知识为第一个问题构造答案。这意味着第二个问题实际上与第一个问题一样困难，尽管第二个问题的描述表面上看起来更简单。

    4 哥德尔不完备定理

    1900 年，伟大的数学家大卫·希尔伯特（David Hilbert）提出了关于数学逻辑基础的以下两个问题：

    1. 算术是一致的吗？
    2. 算术是完备的吗？

    为了理解上述问题，我们回想一下，数学是一个基于公理列表（例如，皮亚诺自然数公理、选择公理等）以及推理规则的正式系统。公理提供了我们系统中最初的真陈述列表，我们可以应用推理规则来证明其他真陈述，我们可以再次使用这些陈述来证明其他陈述，依此类推。

    上面的第一个问题询问是否可能同时证明一个命题 \(P\) 及其否定 \(\neg P\) 。如果是这种情况，那么我们说算术是不一致的；否则，我们说算术是一致的。如果算术是不一致的，意味着可以证明错误的陈述，那么整个算术系统将会崩溃，因为从一个错误的陈述我们可以推导出任何东西，所以我们系统中的每个陈述都将是空洞真（vacuously true）的。

    上面的第二个问题询问是否可以证明算术中的每一个真陈述。如果是这种情况，那么我们说算术是完备的。我们注意到，给定一个陈述（非真即假），要证明它是哪一个可能非常困难。作为一个现实世界的例子，考虑以下陈述，即著名的费马最后定理（Fermat’s Last Theorem）：

    \[ (\forall n \geq 3) \neg (\exists x, y, z \in \mathbb {Z} ^ {+}) (x ^ {n} + y ^ {n} = z ^ {n}). \]

    这个定理最初由皮埃尔·德·费马（Pierre de Fermat）于 1637 年提出，2 但几个世纪以来一直未能得到证明，直到

    1994 年最终由安德鲁·怀尔斯（Andrew Wiles）证明。其他著名的数学陈述，如黎曼猜想（Riemann Hypothesis），至今仍未解决。

    1928 年，希尔伯特正式将上述问题提出为判定问题（Entscheidungsproblem）。大多数人认为答案将是 “yes”，因为理想情况下算术应该是既一致又完备的。然而，在 1930 年，库尔特·哥德尔（Kurt Gödel）证明了答案实际上是 “no”：任何足以使算术形式化的形式系统要么是不一致的（有可以被证明的错误陈述），要么是不完备的（有无法被证明的正确陈述）。哥德尔利用证明与算术之间的深刻联系证明了他的结果。实际上，哥德尔定理也体现了证明与计算之间的深刻联系，这种联系在 1936 年图灵通过图灵机和可计算性的概念将计算定义正式化后得到了阐明。

    在本讲义接下来的部分中，我们将首先简述哥德尔证明的精髓，然后我们将利用我们对停机问题的了解来概述该定理的一个更简单的证明。

    4.1 哥德尔证明简述

    假设我们有一个形式系统 \(F\) ，它由一系列公理和推理规则组成，并假设 \(F\) 的表达能力足够强，我们可以用它来表达所有的算术。

    现在假设我们可以写出以下陈述：

    \[ S (F) = \text {“这个陈述在 F 中不可证明。”} \]

    一旦有了这个陈述，就存在两种可能性：

    1. 情况 1：\(S ( F )\) 是可证明的。那么陈述 \(S ( F )\) 是真的，但通过检查陈述本身的内容，我们发现这意味着 \(S ( F )\) 不应该是可证明的。因此，在这种情况下 \(F\) 是不一致的。
    2. 情况 2：\(S ( F )\) 是不可证明的。根据构造，这意味着陈述 \(S ( F )\) 是真的。因此，在这种情况下 \(F\) 是不完备的，因为存在一个真陈述（即 \(S ( F )\) ）是不可证明的。

    为了完成证明，现在只需构造这样一个陈述 \(S ( F )\) 。这是哥德尔证明中困难的部分，它需要一种巧妙的编码方式（即所谓的“哥德尔数”），将符号和命题编码为自然数。

    4.2 通过停机问题进行证明

    现在让我们看看如何通过规约到停机问题来证明哥德尔的结果。在这里，我们采用反证法：假设算术是既一致又完备的；我们将利用这一假设来解决停机问题，而我们已经知道这是不可能的。

    回想一下，在停机问题中，我们要判定给定的程序 \(P\) 在给定的输入 \(x\) 上是否停机。对于固定的 \(P\) 和 \(x\) ，令 \(S _ { P , x }\) 代表命题“程序 \(P\) 在输入 \(x\) 上停机”。关键的观察是，这个命题可以被表述为一个算术陈述。陈述 \(S _ { P , x }\) 的形式将是：

    \[ \exists z (z \text{ 编码了程序 } P \text{ 在输入 } x \text{ 上的一个有效的停机执行序列}). \]

    虽然细节需要一些工作，但你的编程直觉应该有望说服你，这样的陈述可以以一种相当机械的方式，仅使用标准算术语言，结合通常的运算符、连接词和量词来编写：基本上，该陈述只需要一步一步地检查：

    位串 \(z\) （编码为一个非常长的二进制整数）是否列出了计算机运行程序 \(P\) 并在输入 \(x\) 上执行时所经历的状态序列。

    现在让我们为了得出矛盾而假设，算术是既一致又完备的。这意味着，对于任何 \(( P , x )\) ，陈述 \(S _ { P , x }\) 要么是真的要么是假的，并且在算术中必须存在 \(S _ { P , x }\) 或其否定 \(\neg S _ { P , x }\) 的证明（且不能两者兼有）。但现在回想一下，证明只是一个有限的二进制字符串。因此，只有可数个可能的证明，所以我们可以一个一个地枚举它们，并搜索 \(S _ { P , x }\) 或 \(\neg S _ { P , x }\) 的证明。以下程序执行此任务：

    Search(P, x)
    对于每一个证明 q:
    如果 q 是 \(S_{P,x}\) 的证明 那么 输出 "yes"
    如果 q 是 \(\neg S_{P,x}\) 的证明 那么 输出 "no"

    程序 Search 将程序 \(P\) 作为输入，并开始检查每一个可能的证明，直到找到证明 \(S _ { P , x }\) 或证明 \(\neg S _ { P , x }\) 的证明。根据假设，我们知道这些证明中有一个（且仅有一个）总是存在的，因此程序 Search 将在有限时间内终止，并正确解决停机问题。另一方面，由于我们已经确定停机问题是不可计算的，因此这样的程序 Search 不可能存在。因此，我们最初的假设一定是错误的，所以算术既一致又完备并不是真的。

    请注意，在上述论证中，我们依赖于这样一个事实：给定一个证明，我们可以构造一个程序，机械地检查它是否是给定命题的有效证明。这是证明与计算之间密切联系的体现。
